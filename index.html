01

AI 模型與模式

先把四個常被混在一起的概念拆開。

Model
誰在想。 模型是大腦。較強的模型適合複雜分析；較快的模型適合明確的小修改。
Agent
誰在做。 Codex / Claude Code 能讀專案、改檔案、使用工具，而不只是聊天。
Mode
現在怎麼工作。 Plan 類模式先調查與規劃；執行類模式才真正改程式。
Rules
做事要遵守什麼。 專案規則可以放在 AGENTS.md 或 CLAUDE.md。
適合拿來理解的方式
ClaudeOpus / Sonnet / Haiku 可以先理解成不同能力與速度取向；Plan Mode 是先看清楚再施工。
Codex可以選模型與推理程度；Plan 先分析，Default / Execute 再進行實作。
 
Model   = 工程師的大腦
Agent   = 工程師本人
Plan    = 先看圖、量尺寸
Execute = 開始施工
Rules   = 公司 SOP

03

Git 與 GitHub

先理解用途，不需要先背指令。

Git

專案的版本記錄。每一次 commit 都像一個存檔點，可以看「改了什麼」、比較版本，也能回到過去。

GitHub

放 Git 專案的線上空間，也提供 Issue、Branch、Pull Request、Actions、Pages 等協作與發布功能。

需求 → Branch → 修改 → Test → Pull Request → Merge → main → Deploy
GitHub Pages 適合 HTML / CSS / JavaScript 這種靜態網站。它不會直接替你執行 Python 後端或伺服器端 SQLite。

05

Python：目標是看得懂，不是默寫

AI 可以寫大部分語法，但你仍要能看出資料、條件、流程與錯誤大概在做什麼。

city = "Tokyo"變數：替資料取名字
["Tokyo", "Prague"]List：一串資料
{"city": "Tokyo"}Dictionary：有欄位名稱的資料
if days > 5:if：條件判斷
for trip in trips:for：逐筆處理
def total(...):function：把工作包起來
import jsonimport：使用現成工具
KeyError: 'city'Traceback：錯誤線索
trips = [
    {"city": "Tokyo", "days": 5},
    {"city": "Prague", "days": 7}
]

for trip in trips:
    if trip["days"] > 5:
        print(trip["city"])

只要能翻成白話：「把每趟旅行拿出來，找超過五天的，再印出城市」就已經達到這裡的目標。

07

Connector 與 MCP

讓 AI 能在授權範圍內使用外部服務，而不是每次都靠你複製貼上。

你提出需求
    ↓
Codex / Claude / ChatGPT
    ↓
Connector / MCP
    ↓
Gmail · Drive · Notion · GitHub · Database
Connector / App
產品提供的現成整合。登入並授權後，AI 才能使用整合所提供的資料與操作。
MCP
讓 AI 工具連接外部服務的一種通用協定，可以把它想成「共同插座規格」。
Permission
能讀什麼、能改什麼，不是接上之後就能任意操作整個帳號。
安全觀念 Authentication 確認你是誰；Permission 決定能做什麼；Scope 盡量只給完成任務需要的範圍；寄信、刪除、公開發布等寫入動作要特別確認。
08

把 AI 放進真正的工作流程

不要從「幫我做完」開始，先學會把規劃與執行分開。

先 Plan

先不要修改任何檔案。

請先：
1. 看專案結構
2. 找出需要修改的檔案
3. 說明可能影響的功能
4. 提出實作計畫

再 Execute

依照剛才的計畫實作。

限制：
- 保留現有功能
- 使用繁體中文
- 手機版不能壞
- 完成後自行驗證
需求 → Plan → Branch → AI 實作 → Test → PR → Merge → Deploy
09

建議學習順序

用同一個專案一路往下，不要拆成十個互不相關的小練習。

  1. 01
    GitHub + GitHub Pages

    先知道程式放在哪裡，以及網站怎麼公開。

  2. 02
    README + 專案架構

    學會看 Repo，而不只是看最後畫面。

  3. 03
    Notion + AGENTS.md / CLAUDE.md

    把需求與 AI 規則分開管理。

  4. 04
    Plan → Execute → Test → PR

    建立真正的 AI Coding 工作方式。

  5. 05
    Python 概念

    至少讀得懂 AI 寫的基本程式與錯誤。

  6. 06
    Connector / MCP

    理解 AI 如何跨 Gmail、Drive、Notion、GitHub 等系統工作。

  7. 07
    SQLite → API → Backend

    等真的需要動態資料時再進下一層。
