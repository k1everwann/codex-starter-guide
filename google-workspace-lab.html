Hands-on Lab 01

做一個 Gmail + Google Drive 網站

從零開始建立 GCP Project、啟用 API、設定 OAuth、連接 Apps Script，最後得到一個真的能讀自己 Gmail 與 Google Drive 的 Travel Workspace Dashboard。

完成標準 你能在自己的 Web App 按下按鈕看到旅遊相關 Gmail，並輸入關鍵字搜尋自己的 Drive 檔案。
01

建立 Standard GCP Project

Apps Script 本來會自動配一個 Default Cloud Project。這次故意自己建立 Standard Project，因為我們要真正看懂 API、OAuth 與 Cloud 設定在哪裡。

  1. 開啟 Google Cloud Console ↗。
  2. 上方 Project selector → New Project。
  3. 教學範例名稱可填 Travel Workspace Lab。
  4. 建立完成後，進 IAM & Admin → Settings。
  5. 記下 Project ID 與 Project number。
名稱用途
Project name給人看的名稱，可以修改。
Project IDCloud 裡的唯一字串。
Project number純數字。稍後 Apps Script 的 Change project 要貼這個。
常見錯誤Apps Script 要的是 Project number，不是 Project ID。
02

Enable Gmail API 與 Google Drive API

先告訴 Google：這個 Cloud Project 預計會使用哪些 Google Workspace 服務。

  1. 確認 Cloud Console 上方選到剛建立的 Project。
  2. APIs & Services → Library。
  3. 搜尋 Gmail API → Enable。
  4. 回 Library，搜尋 Google Drive API → Enable。
  5. 到 Enabled APIs & services 確認兩個 API 都存在。
GCP Project
   ├─ Gmail API        ON
   ├─ Google Drive API ON
   ├─ Calendar API     OFF
   └─ ...

可以把 Enable API 想成：不是「有 Google 帳號，所以任何程式都能用 Gmail」，而是這個 Project 明確宣告自己需要哪些服務。

03

設定 Google Auth / OAuth

API 是「服務能不能用」，OAuth 則是「哪個使用者允許這個 App 拿哪些權限」。

Branding

  1. Cloud Console → Google Auth Platform。
  2. 若尚未設定，按 Get Started。
  3. App name：Travel Workspace Dashboard。
  4. User support email / Contact email：填自己的 Google 帳號。

Audience

情況選擇
公司 / 學校 Workspace，只給組織內可能可選 Internal
一般個人 GmailExternal，開發階段先維持 Testing

如果是 External，進 Audience → Test users → Add users，把自己加入測試使用者。

Data Access / Scopes

Scope 是「這個 App 到底要讀什麼、能不能寫」。原則是最小權限：

能 Read 就不要先要 Write
能拿必要資料就不要拿整個帳號權限
這個 Lab 不用自己建立 OAuth Client ID。 因為程式使用 Apps Script built-in services：GmailApp / DriveApp。如果之後改成 Python / Node 直接呼叫 Gmail REST API / Drive REST API，才進一步建立 OAuth Client ID / Client Secret。
04

建立 Apps Script 並綁定 GCP Project

  1. 開啟 Apps Script ↗ → New project。
  2. 名稱可填 Travel Workspace Dashboard。
  3. 左側 Project Settings。
  4. 找到 Google Cloud Platform (GCP) Project → Change project。
  5. 貼上前面記下的 Project number。
  6. 按 Set project。
Apps Script Project

        ▼

        ├─ Drive API
        └─ OAuth settings

這一步是把「程式碼專案」跟「Cloud 權限 / API 專案」連在一起。

06

第一次授權

  1. Apps Script 上方 function 下拉選單選 testAccess。
  2. 按 Run。
  3. 第一次會出現 Google 授權流程。
  4. 確認帳號與要求的權限，再 Allow。
  5. 看 Execution log 是否有紅色 Error。

07

Deploy 成真正的 Web App

  1. 右上角 Deploy → New deployment。
  2. Type 選 Web app。
  3. 私人練習先把存取範圍限制給自己。
  4. Deploy 後取得 https://script.google.com/.../exec。

Execute as 是什麼？

它決定 Backend 用誰的 Google 身分去讀資料。

誰能開網站
      ≠
Backend 用誰的 Google 權限執行
安全不要把一個「以你的 Gmail 權限執行」的 Web App 隨便公開給所有人。練習階段先只開給自己。
08

測試 Gmail 與 Drive

Google Drive

  1. 開 Web App URL。
  2. 輸入一個確定存在的檔名關鍵字，例如 booking 或 東京。
  3. 按 搜尋 Drive。
  4. 應該看到檔名、MIME type、更新日期與 Drive link。

Gmail

  1. 按 載入最近旅遊郵件。
  2. 範例搜尋最近一年、主旨含 flight / hotel / booking / reservation / ticket 的郵件。
  3. 為了隱私，只回傳 Subject、From、Date，不把整封信送到 Browser。

如果你的信件是中文，可以回 Code.gs 修改 query，例如：

newer_than:365d {subject:訂房 subject:機票 subject:預約}

Debug：先找是哪一層壞了

層先看哪裡常見問題

Apps ScriptExecutions / Execution logFunction exception、Gmail / Drive query
GCP / OAuthCloud ConsoleAPI 沒 Enable、綁錯 Project Number、Test user、Permission
 
先不要修改程式。

Expected:
搜尋 Drive 應該回傳檔案。

Actual:
畫面顯示 permission error。

請依序分析：
1. Browser
2. Apps Script execution
3. GCP API enablement
4. OAuth / permissions

先找 root cause，再提出修改方案。
