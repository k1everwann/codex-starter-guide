第一次 Git 流程：只改一句話就好

不用 Terminal，也不用寫新功能。拿你自己的旅遊網站 Repo，完整走一次 Branch → Commit → Pull Request → Merge，就已經很有價值。

今天的任務很小 例如把首頁的一句說明改得更清楚，或加一行「最後更新：2026-08」。不要趁這次順便重做整個網站。
  1. 先開一張 Issue標題可以是「首頁加入最後更新日期」。Issue 就是這次工作的說明單。
  2. 從 main 建一個 Branch例如 feature/home-update-note。把它想成另外開一個安全施工區。
  3. 先叫 AI Plan把 Issue 丟給 Codex / Claude，要求「先說會改哪個檔案，不要立刻修改」。
  4. 只做這一個小修改確認 Plan 沒問題，再讓 AI 修改。Commit message 可以寫 Add homepage update note。
  5. 開 Pull Request，看 Diff先看綠色新增、紅色刪除。看得懂「這次到底改了什麼」比背 Git 指令重要。
  6. Merge 回 main確認網站沒壞，再 Merge。若有 GitHub Pages，等一下就會看到正式網站更新。
✓ 這一關怎樣算完成？ 你有一張 Issue、一個不是 main 的 Branch、一個 Commit、一個 Pull Request，而且最後成功 Merge。程式只改一行也完全可以。
