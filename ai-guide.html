先分清楚：模型、推理強度、工作模式

這三件事常常長在同一個選單裡，所以很容易混在一起。先記一個簡單原則：模型是「哪顆腦」、推理強度是「想多久」、工作模式是「現在能不能動手改專案」。

Model
哪顆腦在想。 不同模型在速度、能力、成本與長任務表現上有不同定位。
Agent
誰在做事。 Codex / Claude Code 不只聊天，還能讀 Repo、改檔案、執行工具與測試。
Reasoning
這次要想多久。 同一個模型通常可以用不同推理強度處理簡單或複雜工作。
Work Mode
現在允許它做什麼。 Plan 先研究與規劃；Execute / Default 類模式才進入實作。
Rules
做事要遵守什麼。 固定規則放在 AGENTS.md 或 CLAUDE.md，不用每次重講。

第一層：模型本身

先只看「這顆模型大概適合什麼」，不要把 Plan 或 High 之類的設定混進來。

Claude Code：模型怎麼選

模型新手先這樣理解
Haiku快、效率高，適合明確的小任務與簡單修改。
Sonnet日常 coding 的主力，速度與能力比較平衡。
Opus複雜推理、架構、難除錯與跨檔分析。
Fable 5最難、最長時間的自主工作；適合大型調查、root cause、架構決策，不是每個小任務都需要。

ChatGPT：GPT-5.6 模型怎麼看

模型新手先這樣理解
GPT-5.6 Luna效率取向。Free / Go 的日常預設與 Think 主要使用 Luna。
GPT-5.6 Sol旗艦主力。適合 coding、研究、規劃與比較複雜的知識工作；符合資格的付費方案會用它支援多個推理強度。
GPT-5.6 Sol Pro最高能力取向，適合很難或需要較長時間完成的工作流程。
不用硬把 Claude 和 GPT 做一對一配對。 它們不是同一家公司、也不是同一套 benchmark。第一階段只需要知道任務大概是「快的小事、日常主力、複雜推理、超難長任務」哪一種。

第二層：推理強度，不是換模型名稱

以目前 ChatGPT 的 GPT-5.6 為例，符合資格的付費方案可以調整推理投入程度。這比較像叫同一位工程師「快速回答」或「多花時間檢查」，而不是每一格都是完全不同的大腦。

選擇適合情況
Instant日常問題、明確小修改、速度優先。
Medium一般需要思考的 coding、分析與規劃。
High複雜除錯、跨檔分析、重要決策。
Extra High希望 GPT-5.6 Sol 投入最高等級推理的困難問題；是否可用取決於方案。
Pro這一項會使用 GPT-5.6 Sol Pro，適合最難與較長時間的工作流程。
不要什麼都開最高。 改一個標題不需要最高推理；先分析一個陌生 Repo 為什麼壞掉，才值得提高 reasoning。速度、成本與任務難度要一起看。

第三層：Plan / Execute 是工作模式

這層回答的不是「哪顆模型比較強」，而是「AI 現在可以做到哪一步」。

工具PlanExecute / Default 類
Claude Code先讀檔、探索、研究與提出計畫，不先修改原始碼。確認方向後，才進行檔案修改、執行與驗證。
Codex先做非破壞性探索與規劃。確認方案後再真正修改專案。
opusplan 到底是什麼？ 它不是一顆叫 opusplan 的模型，也不是 Plan Mode 本身。它是 Claude Code 的特殊模型設定：進入 Plan Mode 時使用 Opus，進入實作時切回 Sonnet。 
Model      = 哪顆腦
Reasoning  = 這次想多久
Work Mode  = 現在能不能動手改
Agent      = 誰去讀檔、執行工具、完成任務
Rules      = 專案 SOP
對新手最重要的不是記住所有型號。 真正有用的是：小任務選快的；複雜問題換強模型或提高推理；範圍不清楚時先 Plan；確認方案後再 Execute。
